# MESIR Perfume — сайт с админкой (Supabase) и приёмом заявок через Telegram

Статический сайт (HTML/CSS/JS) с корзиной, избранным, фильтрами каталога,
переключателем языка (EN/RU), формой «Отправить заявку» вместо онлайн-оплаты
(заявка с контактами уходит продавцу в Telegram) и защищённой паролем
админ-панелью для управления товарами, hero-слайдами и текстами сайта —
все данные хранятся в Supabase (Postgres), не в git, так что правки не
превращаются в бесконечную историю коммитов.

Сайт читает данные **напрямую из Supabase из браузера** (без своей
серверной прослойки) — это на один сетевой перескок быстрее, чем ходить
через собственную Vercel-функцию. Админ-панель, наоборот, всегда пишет
через сервер (свой пароль + секретный ключ Supabase, которые в браузер
никогда не попадают).

## Структура проекта

```
index.html, about.html, contact.html   — страницы сайта
style.css, script.js, data.js, i18n.js — стили и логика витрины
                                          (i18n.js держит прямой fetch к Supabase)
assets/                                 — логотип

admin/index.html, admin.css, admin.js   — сама админ-панель (/admin)

api/order.js                            — заявка из корзины → Telegram
api/admin/login.js                      — вход в админку
api/admin/logout.js                     — выход
api/admin/session.js                    — проверка, залогинен ли
api/admin/data.js                       — отдаёт текущие данные из Supabase
api/admin/save.js                       — записывает изменения в Supabase
api/admin/upload.js                     — загрузка фото в Supabase Storage

lib/auth.js                             — проверка пароля + подпись сессии
lib/supabase.js                         — серверное чтение/запись (для админки)

supabase/schema.sql                     — SQL: создать таблицу (разово)
supabase/seed.sql                       — SQL: заполнить текущим каталогом (разово)
supabase/rls.sql                        — SQL: включить публичное чтение (разово)
supabase/*.json                         — исходники, из которых собран seed.sql
                                           (просто для справки, сайтом не используются)

package.json                            — нужен, чтобы Vercel опознал проект
.env.example                            — какие переменные окружения нужны (для сервера)
```

## Как работает админка

1. Заходишь на `твой-сайт.vercel.app/admin`, вводишь пароль.
2. Правишь товары / слайды / тексты сколько угодно — всё копится только в
   памяти браузера, индикатор «Есть несохранённые изменения» показывает,
   что правки ещё не опубликованы.
3. Жмёшь **«Опубликовать»** в шапке — всё разом уходит в Supabase одним
   проходом (обновляются только реально изменённые разделы) через
   серверную функцию с секретным ключом.
4. Сайт при каждом заходе посетителя читает актуальные данные **напрямую
   из Supabase** — изменения видны почти сразу.

Никаких git-коммитов на каждое действие, никакой истории из сотен мелких
правок — просто база данных, как и положено для активно используемой
админки.

## Настройка Supabase (один раз, перед первым деплоем)

1. Зарегистрируйся на [supabase.com](https://supabase.com) → **New Project**
   (бесплатный план с запасом для такой задачи).
2. Дождись создания проекта, затем **SQL Editor** → **New query** → вставь
   содержимое `supabase/schema.sql` → **Run**. Это создаёт таблицу `site_data`.
3. Новым запросом вставь содержимое `supabase/seed.sql` → **Run**.
   Это заполнит таблицу тем каталогом, что уже есть на сайте.
4. Ещё одним новым запросом вставь содержимое `supabase/rls.sql` → **Run**.
   Это включает публичное **чтение** (нужно, чтобы сайт мог напрямую
   ходить в базу из браузера) и одновременно гарантирует, что **писать**
   через этот публичный доступ нельзя — только через админку.
5. **Storage** (в левом меню) → **New bucket** → назови `uploads` → включи
   **Public bucket** → Create. Сюда админка будет складывать фото товаров.
6. **Project Settings** → **API** (или **API Keys**, в зависимости от
   версии интерфейса Supabase) → тебе нужны **два разных** ключа:
   - **Project URL** (вида `https://xxxxx.supabase.co`)
   - **service_role** ключ (в новой системе Supabase может называться
     **secret**, `sb_secret_...`) — НЕ путать со следующим пунктом
   - **anon** / **public** ключ (в новой системе — **publishable**,
     `sb_publishable_...`) — этот безопасно светить в браузере

   ⚠️ `service_role`/`secret` даёт полный доступ на запись в обход всех
   ограничений — используется только в серверных функциях
   (`lib/supabase.js`, через переменную окружения на Vercel), в браузер
   никогда не передаётся.

   `anon`/`publishable` ключ — наоборот, специально предназначен для
   браузера. Именно после выполнения `rls.sql` (шаг 4) он даёт только
   право на чтение.

### Куда вписать anon/publishable ключ

Это **не** переменная окружения на Vercel — она внедряется прямо в
клиентский код (так задумано у Supabase, ключ рассчитан на публичность).
Открой `i18n.js`, найди рядом с началом файла:

```js
const SUPABASE_URL = 'https://YOUR-PROJECT.supabase.co';
const SUPABASE_ANON_KEY = 'YOUR-ANON-OR-PUBLISHABLE-KEY';
```

Замени оба плейсхолдера на реальные значения из шага 6. Также замени
`https://YOUR-PROJECT.supabase.co` на реальный Project URL в тегах
`<link rel="preconnect" ...>` в `<head>` каждой из трёх HTML-страниц
(`index.html`, `about.html`, `contact.html`) — это ускоряет установку
соединения с Supabase.

## Настройка Telegram-бота (для заявок из корзины)

1. Открой в Telegram чат с **@BotFather**.
2. Отправь `/newbot`, придумай имя и username для бота (должен заканчиваться
   на `bot`, например `mesir_orders_bot`).
3. BotFather пришлёт **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   — это `TELEGRAM_BOT_TOKEN`.
4. Напиши **своему новому боту** любое сообщение — иначе он не сможет
   писать тебе первым.
5. Узнай свой **chat_id**: открой чат с **@userinfobot**, отправь `/start`.
   Числовой ID, который он пришлёт — это `TELEGRAM_CHAT_ID`.

## Деплой на Vercel

1. Замени плейсхолдеры в `i18n.js` и в трёх HTML-файлах (см. выше) на
   реальные значения — сделай это **до** пуша.
2. Залей проект в GitHub-репозиторий.
3. На [vercel.com](https://vercel.com) → **New Project** → выбери репозиторий.
4. Framework Preset — оставь **Other**.
5. **До первого деплоя** зайди в **Project → Settings → Environment Variables**
   и добавь переменные из `.env.example` (это только серверные секреты —
   anon-ключ сюда добавлять не нужно, он уже прямо в коде):
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — для заявок
   - `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` — для входа в админку
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` — для записи данных из админки
6. Нажми Deploy.
7. Проверь заявки: добавь товар в корзину → «Отправить заявку» → заполни
   форму → должно прийти сообщение в Telegram.
8. Проверь админку: открой `/admin`, введи `ADMIN_PASSWORD`, попробуй
   добавить тестовый товар, нажми «Опубликовать» — через несколько секунд
   он должен появиться на сайте (после `rls.sql` изменения видны быстрее,
   чем было через прежнюю серверную прослойку).

**Если после смены переменных окружения ничего не меняется** — Vercel не
подхватывает новые env vars для уже существующих деплоев автоматически.
Deployments → три точки у последнего деплоя → **Redeploy**.

## Важно про бесплатный план Vercel

Hobby (бесплатный) план Vercel по их правилам предназначен только для
некоммерческого использования. Если сайт будет реально принимать заказы —
формально это уже коммерческое использование, и по правилам Vercel нужен
план **Pro** ($20/мес). Технически на Hobby всё будет работать без
ограничений — это вопрос соблюдения условий использования, а не
работоспособности кода.
