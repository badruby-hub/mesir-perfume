# MESIR Perfume — сайт с админкой (Supabase) и приёмом заявок через Telegram

Статический сайт (HTML/CSS/JS) с корзиной, избранным, фильтрами каталога,
переключателем языка (EN/RU), формой «Отправить заявку» вместо онлайн-оплаты
(заявка с контактами уходит продавцу в Telegram) и защищённой паролем
админ-панелью для управления товарами, hero-слайдами и текстами сайта —
все данные хранятся в Supabase (Postgres), не в git, так что правки не
превращаются в бесконечную историю коммитов.

## Структура проекта

```
index.html, about.html, contact.html   — страницы сайта
style.css, script.js, data.js, i18n.js — стили и логика витрины
assets/                                 — логотип

admin/index.html, admin.css, admin.js   — сама админ-панель (/admin)

api/site-data.js                        — публичный эндпоинт: сайт читает
                                           товары/слайды/тексты отсюда
api/order.js                            — заявка из корзины → Telegram
api/admin/login.js                      — вход в админку
api/admin/logout.js                     — выход
api/admin/session.js                    — проверка, залогинен ли
api/admin/data.js                       — отдаёт текущие данные из Supabase
api/admin/save.js                       — записывает изменения в Supabase
api/admin/upload.js                     — загрузка фото в Supabase Storage

lib/auth.js                             — проверка пароля + подпись сессии
lib/supabase.js                         — чтение/запись данных в Supabase

supabase/schema.sql                     — SQL для создания таблицы (разово)
supabase/seed.sql                       — SQL с текущим каталогом (разово)
supabase/*.json                         — исходники, из которых собран seed.sql
                                           (просто для справки, сайтом не используются)

package.json                            — нужен, чтобы Vercel опознал проект
.env.example                            — какие переменные окружения нужны
```

## Как работает админка

1. Заходишь на `твой-сайт.vercel.app/admin`, вводишь пароль.
2. Правишь товары / слайды / тексты сколько угодно — всё копится только в
   памяти браузера, индикатор «Есть несохранённые изменения» показывает,
   что правки ещё не опубликованы.
3. Жмёшь **«Опубликовать»** в шапке — вот только теперь всё разом уходит
   в Supabase одним проходом (обновляются только реально изменённые
   разделы).
4. Сайт при каждом заходе посетителя читает актуальные данные из Supabase
   через `/api/site-data` — изменения видны почти сразу (кешируется на
   ~30 секунд на edge, чтобы не дёргать базу на каждый чих).

Никаких git-коммитов на каждое действие, никакой истории из сотен мелких
правок — просто база данных, как и положено для активно используемой
админки.

## Настройка Supabase (один раз, перед первым деплоем)

1. Зарегистрируйся на [supabase.com](https://supabase.com) → **New Project**
   (бесплатный план с запасом для такой задачи).
2. Дождись создания проекта, затем **SQL Editor** → **New query** → вставь
   содержимое `supabase/schema.sql` → **Run**. Это создаёт таблицу `site_data`.
3. Там же новым запросом вставь содержимое `supabase/seed.sql` → **Run**.
   Это заполнит таблицу тем каталогом, что уже есть на сайте — дальше
   правишь через админку, а не руками в SQL.
4. **Storage** (в левом меню) → **New bucket** → назови `uploads` → включи
   **Public bucket** → Create. Сюда админка будет складывать фото товаров.
5. **Project Settings** (шестерёнка) → **API** → скопируй:
   - **Project URL** → это `SUPABASE_URL`
   - **service_role** ключ (не `anon`/`public`!) → это `SUPABASE_SERVICE_ROLE_KEY`

   ⚠️ `service_role` даёт полный доступ на запись в обход всех ограничений
   — используется только в серверных функциях (`lib/supabase.js`), в
   браузер никогда не передаётся. Не публикуй его нигде.

## Настройка Telegram-бота (для заявок из корзины)

1. Открой в Telegram чат с **@BotFather**.
2. Отправь `/newbot`, придумай имя и username для бота (должен заканчиваться
   на `bot`, например `mesir_orders_bot`).
3. BotFather пришлёт **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   — это `TELEGRAM_BOT_TOKEN`.
4. Напиши **своему новому боту** любое сообщение — иначе он не сможет
   писать тебе первым.
5. Узнай свой **chat_id**: открой чат с **@userinfobot**, отправь `/start`.
   Числовой ID, который он пришлёт — это `TELEGRAM_CHAT_ID`.

## Деплой на Vercel

1. Залей проект в GitHub-репозиторий.
2. На [vercel.com](https://vercel.com) → **New Project** → выбери репозиторий.
3. Framework Preset — оставь **Other**.
4. **До первого деплоя** зайди в **Project → Settings → Environment Variables**
   и добавь все переменные из `.env.example`:
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — для заявок
   - `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` — для входа в админку
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` — для хранения данных
5. Нажми Deploy.
6. Проверь заявки: добавь товар в корзину → «Отправить заявку» → заполни
   форму → должно прийти сообщение в Telegram.
7. Проверь админку: открой `/admin`, введи `ADMIN_PASSWORD`, попробуй
   добавить тестовый товар, нажми «Опубликовать» — через ~30 секунд он
   должен появиться на сайте.

**Если после смены переменных окружения ничего не меняется** — Vercel не
подхватывает новые env vars для уже существующих деплоев автоматически.
Deployments → три точки у последнего деплоя → **Redeploy**.

## Важно про бесплатный план Vercel

Hobby (бесплатный) план Vercel по их правилам предназначен только для
некоммерческого использования. Если сайт будет реально принимать заказы —
формально это уже коммерческое использование, и по правилам Vercel нужен
план **Pro** ($20/мес). Технически на Hobby всё будет работать без
ограничений — это вопрос соблюдения условий использования, а не
работоспособности кода.
